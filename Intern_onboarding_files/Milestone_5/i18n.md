# Implementing Internationalization with i18next #21

## What I built

I added i18next to my React project (`onboarding-task-test-project`):

- `src/i18n.js` sets up i18next with `initReactI18next`, English as the default language and English as the fallback language.
- `src/locales/en.json` and `src/locales/es.json` hold the English and Spanish translations.
- `src/main.jsx` imports `./i18n` once, so i18next is ready before the app renders.
- `src/HelloWorld.jsx` uses `useTranslation()` to show translated text, passes the user's name with interpolation (`t('welcome', { name })`), and has a button that calls `i18n.changeLanguage()` to switch between English and Spanish.

## What challenges did you face while setting up i18next?

- Remembering to import `./i18n` in `main.jsx`. If the file is never imported, i18next is never initialised and `t()` just shows the key names (like `welcome`) instead of the text.
- Deciding how to organise the translation files. I kept one JSON file per language in `src/locales/` and used the same keys in both, so a missing key is easy to spot.
- Learning the interpolation syntax. Values are written as `{{name}}` in the JSON and passed as an object to `t()`. I also set `escapeValue: false` because React already escapes values, so i18next does not need to.
- Making sure the page updates when the language changes. Because the component uses the `useTranslation` hook, it re-renders automatically after `changeLanguage()`, and I did not need to manage any extra state.

## Why is it important to use a library like i18next instead of manually handling translations?

Doing it by hand quickly turns into lots of `if (language === 'es')` checks spread across components, which is hard to maintain. i18next already handles the common problems:

- Interpolation for inserting values into sentences, and plural rules that differ between languages.
- Fallback languages, so the app still shows English if a translation is missing.
- Changing language at runtime, with React components re-rendering automatically.
- Plugins for detecting the browser language, saving the user's choice and lazy loading translation files.
- Keeping all text in JSON files, which translators can edit without touching the code and which translation platforms can import.

## How would you handle dynamic content (e.g., user-generated text) in a multilingual app?

- Only translate the interface with i18next. User-generated text (notes, task names, comments) should be stored exactly as the user wrote it, because the translation files cannot know it in advance.
- Save the language of the content with it (for example a `language` field), so the app knows what language each piece of text is in.
- If other users need to read it in their own language, translate it on demand with a translation API, cache the result, and label it as machine translated with an option to see the original.
- Use interpolation for sentences that mix fixed text and dynamic values (for example `Welcome, {{name}}!`), instead of joining strings together, because word order changes between languages.
- Format dates, numbers and currency with the user's locale (`Intl.DateTimeFormat`, `Intl.NumberFormat`), and make sure the layout works for right-to-left languages such as Arabic.
